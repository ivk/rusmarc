RUSMARC
=======

Библиотека на Python для чтения, разбора и сборки библиографических записей
в формате **RUSMARC** (обменный формат ISO 2709). Рядом с библиотекой лежит
утилита ``read.py``: она проходит файл или каталог выгрузок, печатает сводку
по полям и по желанию складывает записи в SQLite или отделяет битые записи
от целых.

Запись в памяти — это словарь полей. Контрольные поля (001–009) хранятся
строками, поля данных (от 010) — индикаторами и списком подполей. Из этой
структуры запись можно снова собрать в ISO 2709 или напечатать в текстовом
виде, где подполя обозначены знаком ``$``.


Установка
---------

Нужен Python 3. Сторонних зависимостей нет: ``requirements.txt`` пустой,
для работы достаточно стандартной библиотеки.

Из каталога проекта::

    pip install -e .

После этого импортируется пакет ``rusmarc``. Скрипт ``read.py`` в пакет
не входит и запускается из корня репозитория.

База SQLite отдельно не создаётся. Её пишет ``read.py`` с флагом ``-d``,
запускать нужно из корня репозитория: путь к файлу относительный.
Каталог ``db/`` должен уже быть на месте. Если файла нет, SQLite создаёт его
при первом таком запуске. Имя файла всегда одно: ``db/rusmarc.db``.

::

    python read.py marcfiles/example.iso -enc cp1251 -d

Таблица внутри базы называется по имени файла или каталога, который передан
в команду. В имени таблицы допустима только латиница: имя подставляется
в SQL как есть, без кавычек. Файл с кириллическим именем перед разбором
нужно переименовать, например ``Выгрузка.iso`` в ``vygruzka.iso``. Если в имени
есть точка и оно длиннее четырёх символов, отбрасываются последние четыре
символа: ``vygruzka.iso`` даёт таблицу ``vygruzka``. Повторный запуск с тем же
именем удаляет эту таблицу и создаёт её заново.


Состав репозитория
------------------

``rusmarc/rusmarc.py``
    Класс ``Rusmarc`` и исключение ``MalformedRecord``. Разбор одной записи
    и обратная сборка.

``rusmarc/rusmarc_iter.py``
    Итераторы по файлу ISO 2709. Для чтения выгрузок используйте
    ``MarcFileIterator``.

``read.py``
    Командная утилита: обход файла или каталога, отчёт по полям, запись
    в SQLite, отдельное сохранение целых и повреждённых записей.

``rusmarc/convert.py``
    Черновик чтения файла. Разбор аргументов не связан с ``main``,
    преобразование MARC 21 в RUSMARC не реализовано. Заготовка
    соответствия тегов лежит в ``fields.txt``.

``marcfiles/``
    Примеры выгрузок (``.iso``, ``.mrc``). В документацию и в пакет
    не входят.

``db/``
    Каталог, куда ``read.py`` пишет ``rusmarc.db``, если передан флаг ``-d``.

``tests/``
    Проверки кругового преобразования записи (байты → объект → байты)
    и сверка текстового дампа с ``tests/data/TEST1.txt``.


Утилита read.py
---------------

Запуск из корня репозитория::

    python read.py путь/к/файлу.iso
    python read.py путь/к/файлу.mrc -enc cp1251
    python read.py путь/к/каталогу -enc UTF-8 -d

Аргументы:

``filename``
    Файл или каталог. Если передан каталог, читаются только файлы в нём,
    без вложенных папок. Флаги ``-f`` и ``-b`` в этом режиме отключаются.

``-enc``, ``--encoding``
    Кодировка полей: ``UTF-8`` (по умолчанию), ``cp1251`` или ``cp866``.

``-d``, ``--save_db``
    Записать разобранные записи в ``db/rusmarc.db``.

``-f``, ``--save_file``
    Дописать каждую успешно прочитанную исходную запись в
    ``marcfiles/newmarc.iso``. Файл при старте удаляется и создаётся заново.

``-b``, ``--save_bad_records``
    Сложить сырые байты записей, которые итератор или разбор счёл
    повреждёнными, в ``marcfiles/corrupted.iso``.

Ошибки разбора дописываются в ``corrupted.log`` в корне репозитория.
В конце печатается число записей и ошибок, список номеров полей и образец
значения из первой успешной записи. Для части номеров подставляется
название из словаря ``standard_fields`` в ``read.py`` (ISBN, заглавие,
автор, УДК и другие часто встречающиеся поля RUSMARC). Незнакомый номер
подписывается как ``unknown field``.

SQLite
~~~~~~

Таблица создаётся заново при каждом запуске с ``-d``: существующая таблица
с тем же именем удаляется. Имя берётся из базового имени файла или каталога
и должно состоять из латиницы, поэтому исходный файл перед запуском
переименовывают. Если в имени есть точка и оно длиннее четырёх символов,
отбрасываются последние четыре символа (``vygruzka.iso`` превращается
в ``vygruzka``).

Колонки — ``id`` и по одной текстовой колонке ``fieldNNN`` на каждый номер
поля, встретившийся в выгрузке. Значение колонки — подполя через запятую.
Индикаторы, коды подполей и вложенность встроенных полей при этой записи
не сохраняются. Повторения поля тоже склеиваются в одну строку. Для точной
работы с записью нужен объект ``Rusmarc``, а не строка в SQLite.


Кодировки
---------

Одна выгрузка — одна кодировка. Смешивать ``utf-8`` и ``cp1251`` в одном
файле библиотека не умеет.

Признак удачного выбора — читаемые кириллические заглавия в поле 200.
Если ``serialize`` вызывается с той же кодировкой, что и разбор, байты
записи совпадают с исходными: это проверяет ``tests/test_rusmarc.py``
на файле в ``cp1251``.


Ограничения
-----------

- Пакет объявлен как ``0.1a0``. В ``setup.py`` в классификаторах всё ещё
  указан Python 2, код рассчитан на Python 3.
- ``RusmarcFileIterator`` на Python 3 не проходит первую запись из-за
  проверки типа после бинарного чтения.
- ``convert.py`` только читает файл в список словарей и не конвертирует
  MARC 21 в RUSMARC. Соответствие части тегов набросано в ``fields.txt``.
- Карта справочника в позициях 20–23 при чтении не сверяется с ``450``.
- Запись в SQLite теряет индикаторы, коды подполей и структуру встроенных
  полей.
- Текстовый формат ``serialize_marc_txt`` нельзя загрузить обратно.


Разработка
----------

Тесты лежат в ``tests/`` и запускаются из корня репозитория. Им используют
файлы ``tests/data/``, которых в дереве исходников может не быть
(в репозитории есть текстовый эталон ``TEST1.txt``). Запуск отдельного
файла::

    python tests/test_rusmarc.py
    python tests/test_rusmarc_iter.py

Круговая проверка: прочитать запись, собрать ``serialize`` в той же
кодировке и сравнить байты с исходными.
